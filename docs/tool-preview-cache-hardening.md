# 工具文本预览与扩展刷新优化

## PiMac 文本 UI

- 工具详情文本使用独立 `ToolOutputPresentation`，将原生 TextKit 输入限制在 128 KiB / 2,000 行以内，避免巨大输出直接进入同步字形布局。UTF-8 截断不切断 Unicode scalar；CRLF、CR 和 Unicode 换行符均受行数限制。
- 新增不区分大小写的字面搜索、上下匹配导航与 Escape 关闭；搜索仅覆盖预览，最多返回 1,000 个匹配。
- 新增自动换行开关；窗口宽度改变时重新布局，SwiftUI 分配 frame 前即可测量换行高度。修复 TextKit 在切换换行后可能报告千万点宽度的问题。
- 复制和保存 `.txt` 始终使用完整原文，不使用截断预览；保存错误显示原生错误提示。
- 原生文本搜索范围使用减法检查，拒绝负数、越界和整数溢出范围，同时保留用户手动选择。

这些能力适用于详情视图实际收到的文本（包括工具输入）。**不修改官方 T3 V2 projection，不恢复被上游移除的工具输出／图片。** 详情视图可用，不代表官方服务已提供完整输出。

## account-usage

- 缓存容量策略提取为纯函数，按真实 UTF-8 字节计算 1 MiB 文档上限；只在容量不足时淘汰旧条目，保护当前写入；单条超限不会破坏此前缓存。
- 每次发布附带可选随机 revision。重叠的手动刷新可复用调用开始后发布的新快照，连续手动刷新仍访问网络；旧版 version-1 缓存无须迁移。
- provider namespace 锁仍覆盖查询，文档锁仅覆盖合并；保持账户身份、有效期、取消与验证检查。不会把过期额度作为新鲜额度，也不会添加付费请求或扩大自动轮换范围。
- HTTP 参数拒绝 Node 定时器溢出、无效重试预算、非 HTTPS 与 URL 内嵌凭据，所有检查在 fetch 前完成。

## 验证与限制

新增测试覆盖预览字节／换行限制、Unicode 字面搜索、换行／宽度调整、搜索范围溢出、缓存淘汰、强制刷新合并及请求参数校验。测试使用合成数据与临时目录，不读取真实账户，也不发送付费模型请求。

运行完整检查：`./scripts/check.sh`。真实 OAuth、手机连接和大文本交互仍需要实机验收；不自动重启运行中的应用，不发布 release。
